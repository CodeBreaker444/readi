A **System** in Readi is any physical asset tracked as a `tool` record in the database.

## System Fields

| Field | DB Column | Meaning |
|---|---|---|
| Asset code | `tool.tool_code` | Unique identifier (e.g. `DJI-M3T-001`) |
| Name | `tool.tool_name` | Display name |
| Active flag | `tool.tool_active` | `Y` = in service, `N` = decommissioned |
| Location | `tool.location` | Physical storage location |
| Activation date | `tool_metadata.activationDate` | When the asset entered service |
| Client assignment | `tool_metadata.clientId` | Which client this drone is dedicated to |
| Calibration | `tool.last_calibration_date` / `tool.next_calibration_date` | Calibration tracking |
| Warranty | `tool.warranty_expiry` | Warranty end date |

Each system can have **components** (`tool_component`): motors, batteries, sensors — each tracked individually for usage hours and expiry.

---

## Operational Status

Computed live on every fleet load. **Not a stored field.**

```
NOT_OPERATIONAL  >  MAINTENANCE  >  OPERATIONAL
```

| Status | Trigger condition |
|---|---|
| `OPERATIONAL` | No open tickets, no expired components |
| `MAINTENANCE` | Open maintenance ticket (`ticket_status != CLOSED`) OR component with `component_status = MAINTENANCE` |
| `NOT_OPERATIONAL` | Active component (`component_active = Y`) has `expiration_date <= today` (or has reached a flight / flight-hour limit) |

<Warning>
A system can satisfy both MAINTENANCE and NOT_OPERATIONAL simultaneously. NOT_OPERATIONAL always wins the display.
</Warning>

See [System Status Rules](/docs/platform-rules/system-status-rules) for the full computation.

## Decommissioned

**Manual:** Admin sets `tool_active = N` via Settings → Systems.

**Automated:** Components decommission automatically when they expire, that is, when they pass their expiry date or reach their flight or flight-hour limit. An expired component shows as Decommissioned and the system becomes Not Operational. The platform also sends expiration notifications to managers.

<Warning>
**Expiry is permanent by default.** An expired component cannot be made operational again and no maintenance ticket can be created for it. The system stays `NOT_OPERATIONAL` until the component is removed from it (removed, or moved to the warehouse). Setting the component to Decommissioned does not free the system.
</Warning>

### Renewable expiry (`expiry_permanent = false`)

The **Permanent expiry** checkbox on a component is stored as `tool_component.component_metadata.expiry_permanent`. A missing value means `true`, so every component created before the option existed is permanent.

| | `expiry_permanent = true` (default) | `expiry_permanent = false` |
|---|---|---|
| Effective status when expired | `DECOMMISSIONED` | `NOT_OPERATIONAL` (an explicit stored `MAINTENANCE`, `DECOMMISSIONED` or `DISMISSED` is kept) |
| System status when expired | `NOT_OPERATIONAL` until the component is removed from the system (detached / warehouse / removed). `DECOMMISSIONED` does not free it | `NOT_OPERATIONAL` until renewed, `DECOMMISSIONED`, or removed |
| Maintenance ticket | Cannot be created | Created by a user, never automatically |
| Renewing the limits by editing | Refused | Refused while expired (error `expiredRenewViaTicket`). Renewed when a ticket covering it is closed. Editable again once it is no longer expired |
| Changing the flag while expired | Refused | Refused |

When a renewable component expires it becomes `NOT_OPERATIONAL` and stays that way until a ticket covering it is closed (which renews its expiry) or it is set to `DECOMMISSIONED`. **No maintenance ticket is created automatically.**

While it is expired, editing its expiry (`expiry_type`, `expiration_date`, `expiration_flights`, `expiration_flight_hours`) or the counters that could clear it is refused with the error `expiredRenewViaTicket`. Other fields can still be edited.

**Renewal when the ticket closes.** `closeTicket` renews every component on the ticket (or every component of the system, for a system-level ticket) that has `expiry_permanent = false`, is still in the system (not detached, decommissioned or dismissed) and has reached a limit. The amounts are constants in `src/lib/system/expiry-renewal.ts`:

| Limit | New value |
|---|---|
| `expiration_date` | the later of the old date and today, plus 1 month (the day is clamped to the end of a shorter month) |
| `expiration_flights` | old limit + 10 |
| `expiration_flight_hours` | the later of the old limit and `current_usage_hours`, plus 10 |

Only the limits that were reached are renewed (a `MIXED` component keeps the others). The renewal is planned before the counters are reset, because the flight counter is part of the check. Each renewal adds an `EXPIRY_RENEWED` event to the ticket timeline and is written to the audit log. `GET /api/system/maintenance/tickets/expiry-renewals?ticket_id=` returns the same plan for the Close Ticket window.

A user can put it on a maintenance ticket: an expired renewable component is ticketable even though its status is `NOT_OPERATIONAL`. A component with a stored `NOT_OPERATIONAL` (for example from a reported issue), `DECOMMISSIONED` or `DISMISSED` status, or a detached one, is still not ticketable. Closing the ticket resets the component's counters and renews its expiry (see below).

When a ticket is created for a system whose stored status is `OPERATIONAL` (or empty) but that is `NOT_OPERATIONAL` because of an expired component, the system's stored status is set to `MAINTENANCE`, so the fleet list shows Maintenance. This applies to permanent and renewable expiry (for a permanent expired component, through a ticket for another component or for the whole system). It is set back to `OPERATIONAL` when the last open ticket closes; if an expired component is still in the system, the computed `NOT_OPERATIONAL` shows again. A status set by hand (`NOT_OPERATIONAL`, `DISMISSED`, ...) is never overwritten.

| State | `tool_active` | In fleet? | Missions? |
|---|---|---|---|
| In service | `Y` | Yes | Yes |
| Decommissioned | `N` | No | No |
| Soft-deleted | `Y` but `tool_metadata.deleted = true` | No | No |
| Warehouse | `Y` but `tool_metadata.is_warehouse = true` | No | No |

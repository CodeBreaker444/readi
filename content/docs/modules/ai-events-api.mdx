title: "AI Events API"
description: "How the AI model sends detection events to ReADI: endpoint, authentication, payload, validation rules and responses."
---

The AI model reports detections (for example an intruder on a video stream) to ReADI with a single HTTPS request. ReADI stores every event. A company sees an event in the **AI events** tab of its [Event Logbook](/docs/modules/logbooks#ai-events) once one of its admins has added the event's **stream id**, and that company's chosen recipients are then emailed.

---

## How events reach a company

The model does not know which company a camera belongs to, so the request carries no company. Instead:

1. The model sends the event to ReADI. It is **stored as it is**.
2. An admin of a company adds the camera's `stream_id` in **AI streams** in the Event Logbook. The stream id is now that company's, and **only one company can hold a given stream id**.
3. From then on, and for events already stored, that company sees the events of the stream id, and the alert emails it configured are sent.

Events whose stream id nobody has added are **only stored**: no company sees them and no email is sent. Super admins see all events and which company (if any) holds each stream id.

---

## Endpoint

```
POST /api/ai-events/ingest
Content-Type: application/json
X-API-KEY: <AI events key>
```

Send one event per request. The request is answered as soon as the event is stored; sending the alert email happens afterwards, so the call stays fast.

---

## Authentication

Because the model is not tied to a company, this endpoint does **not** use the per-company API keys from Settings. It uses one **platform key**, which the person running the ReADI server sets in the environment:

```
AI_EVENTS_API_KEY=<a long random secret>
```

Give the same value to the model and send it in the `X-API-KEY` header of every request. Generate a long random value (for example 32 random bytes in hex) and restart the server after setting it.

<Warning>
Treat the key like a password and keep it on the server running the model. Whoever holds it can add events for any stream id. To rotate it, change the environment value and the model's copy together.
</Warning>

## Request body

**Every field is required.** A payload with a missing or `null` field is rejected with `400` and nothing is stored. The only value that may be `null` is `error` inside `org_img` and `ai_processed_img` (the key itself must be present). Unknown extra fields are ignored.

```json
{
  "event_type": "INTRUSION_DETECTED",
  "stream_id": "test_video_1",
  "session_id": "50134c7a-a99b-45b2-91ec-7fd1ba173d98",
  "track_id": 1,
  "class_name": "person",
  "confidence": 0.9247,
  "timestamp": "2026-11-02 14:38:59",
  "frame_number": 20,
  "bounding_box": [78.97, 245.36, 385.15, 604.1],
  "frames_detected": 1,
  "processing_time_ms": 0.0,
  "model_mode": "REGULAR",
  "s3_upload_status": "uploaded",
  "snapshot": {
    "local_path": "intrusions/<stream_id>/<file>_processed.jpg",
    "s3_key": "ai_alerts/<stream_id>/<session_id>/<file>_ai_processed.jpg",
    "s3_upload_status": "uploaded"
  },
  "org_img": {
    "local_path": "intrusions/<stream_id>/<file>_org.jpg",
    "s3_key": "ai_alerts/<stream_id>/<session_id>/<file>_org.jpg",
    "upload_status": "uploaded",
    "resolution": { "width": 1280, "height": 720 },
    "error": null
  },
  "ai_processed_img": {
    "local_path": "intrusions/<stream_id>/<file>_processed.jpg",
    "s3_key": "ai_alerts/<stream_id>/<session_id>/<file>_ai_processed.jpg",
    "upload_status": "uploaded",
    "resolution": { "width": 1280, "height": 720 },
    "error": null
  },
  "ai_processed_img_res": { "width": 640, "height": 384 },
  "detections": [
    { "track_id": 1, "class_name": "person", "confidence": 0.9247, "bounding_box": [78.97, 245.36, 385.15, 604.1] },
    { "track_id": 4, "class_name": "bus", "confidence": 0.8394, "bounding_box": [18.19, 151.57, 1274.53, 493.24] }
  ]
}
```

### Fields and validation

Text values are trimmed first and must not be empty.

**The event**

| Field | Type | Rules | Used for |
|---|---|---|---|
| `event_type` | string | 1–50 characters. Stored in upper case. | The event type, shown as words (`INTRUSION_DETECTED` → "Intrusion Detected"). |
| `stream_id` | string | 1–200 characters. Matched **exactly** (case-sensitive) with the stream ids companies added. | Decides which company sees the event and who is emailed. |
| `session_id` | string | 1–100 characters. | The run of the model. Part of the duplicate check. |
| `track_id` | integer | Whole number. | The object that triggered the event. Part of the duplicate check. |
| `class_name` | string | 1–100 characters. | What was detected, for example `person`. |
| `confidence` | number | From `0` to `1`. Shown as a percentage. | Detection confidence. |
| `timestamp` | string | See [Timestamps](#timestamps). | When the event happened. |
| `frame_number` | integer | `0` or more. | Frame of the detection. |
| `bounding_box` | array of 4 numbers | Exactly 4 numbers, `[x1, y1, x2, y2]`, in pixels of the **original** frame (`org_img.resolution`). | Position of the triggering object. |
| `frames_detected` | integer | `0` or more. | Frames the object was seen in. |
| `processing_time_ms` | number | `0` or more (`0.0` is fine). | Model processing time. |
| `model_mode` | string | 1–50 characters. | Mode the model ran in, for example `REGULAR`. |
| `s3_upload_status` | string | 1–50 characters. `uploaded` when the upload finished. | Whether the snapshot can be used. |

**`snapshot`**

| Field | Rules |
|---|---|
| `snapshot.local_path` | 1–500 characters. Required, not used by ReADI. |
| `snapshot.s3_key` | An [image key](#images). |
| `snapshot.s3_upload_status` | 1–50 characters. `uploaded` when finished. |

**`org_img` (original frame) and `ai_processed_img` (frame with the model's boxes drawn)**

| Field | Rules |
|---|---|
| `local_path` | 1–500 characters. Required, not used by ReADI. |
| `s3_key` | An [image key](#images). |
| `upload_status` | 1–50 characters. Only `uploaded` images are used. |
| `resolution` | `{ "width": …, "height": … }`, positive whole numbers. For `org_img` this is the coordinate space of all bounding boxes. |
| `error` | A string (at most 1000 characters) or `null`. The key must be present. |

**`ai_processed_img_res`**: `{ "width": …, "height": … }`, positive whole numbers. The size the model processed the frame at.

**`detections`**: array of up to 200 objects, one per object in the frame, each with `track_id` (integer), `class_name` (1–100 characters), `confidence` (`0` to `1`) and `bounding_box` (exactly 4 numbers). It may be empty. The detection whose `track_id` equals the event's `track_id` is shown as the main one.

### Images

The model uploads the images **straight into ReADI's S3 bucket** and sends only their keys; ReADI never downloads anything from the request. Every `s3_key` must:

- start with `ai_alerts/`
- contain only letters, digits and `. _ - /`
- not contain `..` or `//`
- be at most 500 characters

Keys that break these rules are rejected with `400`, so a request can never point at another file in the bucket. An image is only used when the model reports its upload as `uploaded`. If none is, the event is stored with **Snapshot unavailable**; if only one is, the event shows the other. Make sure the file is in the bucket **before** you send the event, because ReADI links to it as soon as the event is shown or emailed.

### Timestamps

Two forms are accepted:

| Form | Example | How it is read |
|---|---|---|
| Without a time zone | `2026-11-02 14:38:59` (a `T` instead of the space also works; fractions of a second are allowed) | As **IST (UTC+5:30)**, the model's local time. `14:38:59` is stored as `09:08:59Z`. |
| With a time zone | `2026-11-02T09:08:59Z` or `2026-11-02T14:38:59+05:30` | As written. The `T` is required. |

Impossible dates (`2026-13-02`, `2026-02-30`, hour `25`) are rejected. The offset for values without a time zone can be changed on the server with the `AI_EVENTS_TIMEZONE_OFFSET_MINUTES` setting (default `330`).

## Responses

| Status | When | Body |
|---|---|---|
| `201 Created` | New event stored. | `{ "code": 200, "ai_event_id": 12, "duplicate": false, "claimed": true }` |
| `200 OK` | The same event was already received (see [Duplicates](#duplicates)). Nothing new is stored or emailed. | `{ "code": 200, "ai_event_id": 12, "duplicate": true, "claimed": true }` |
| `400 Bad Request` | The body is not valid JSON, a field is missing, null or invalid, or the timestamp cannot be read. | See below. |
| `401 Unauthorized` | `X-API-KEY` missing or wrong. | `{ "code": 0, "status": "ERROR", "error": "Invalid API key" }` |
| `409 Conflict` | An event with the same five duplicate-check values exists but could not be matched (rare). | `{ "code": 0, "status": "ERROR", "error": "An event with the same stream_id, …already exists.", "errorCode": "EVENT_CONFLICT", "retryable": false }` |
| `500` | The server could not store the event. The message says why when it can, for example that the database migrations have not been run. | See [Server errors](#server-errors). |
| `503 Service Unavailable` | `AI_EVENTS_API_KEY` is not set on the server (see above), **or** the database is temporarily unreachable. | See [Server errors](#server-errors). |

`ai_event_id` is the id of the event in ReADI. `claimed` tells you whether a company has added the stream id at the moment of the request. `false` is not an error: the event is stored, and becomes visible once a company adds the stream id.

### Validation errors

`400` responses list every problem, keyed by the **full path** of the field:

```json
{
  "code": 0,
  "error": "Validation failed",
  "errorCode": "VL001",
  "errors": {
    "confidence": ["Too big: expected number to be <=1"],
    "org_img.s3_key": ["Invalid input: expected string, received undefined"],
    "ai_processed_img.s3_key": ["must start with \"ai_alerts/\" and contain only letters, digits and . _ - /"]
  }
}
```

A body that is not valid JSON returns `{ "code": 0, "error": "Body must be valid JSON" }`, and an unreadable timestamp returns an `error` that describes the accepted formats.

### Server errors

When ReADI cannot store an event for a reason that is not in your payload, the response says what kind of problem it is, whether trying again can help, and a **reference**. The full technical error is written to the server log under that reference, so give it to the ReADI administrator. Raw database messages are never returned.

```json
{
  "code": 0,
  "status": "ERROR",
  "error": "The server database is not up to date with this version of the API (a required table or column is missing). Ask the ReADI administrator to run the pending database migrations. Reference: 3fa91c0e",
  "errorCode": "DB_SCHEMA_OUTDATED",
  "retryable": false,
  "reference": "3fa91c0e"
}
```

| `errorCode` | Status | `retryable` | Meaning and action |
|---|---|---|---|
| `EVENT_REJECTED` | `400` | `false` | The event was refused, for example an unreadable `timestamp`. The message says why. Fix the payload. |
| `EVENT_CONFLICT` | `409` | `false` | An event with the same duplicate-check values already exists. Nothing to do. |
| `DB_SCHEMA_OUTDATED` | `500` | `false` | The server database is missing a table or column. The ReADI administrator must run the pending migrations; retrying will not help until then. |
| `DB_UNAVAILABLE` | `503` | `true` | The database is temporarily unreachable. Send the **same** request again in a moment. |
| `STORE_FAILED` | `500` | `true` | Unexpected error. Retry with the same payload; if it keeps failing, give the `reference` to the ReADI administrator. |

### Duplicates

An event is a duplicate when ReADI already holds one with the same `stream_id`, `session_id`, `track_id`, `event_type` and `timestamp`. Resending it is safe: the response is `200` with `"duplicate": true`, and no second row or email is created. Use this to retry after a network error or a `5xx`. A new detection must differ in at least one of these five values; the same detection reported for a different `stream_id` is a separate event.

## What happens after the request

1. The event is stored and the response is sent.
2. If a company holds the `stream_id` and has email alerts switched on for it, one email goes to the recipients that company chose (the client's address if enabled, plus the selected contacts), with both images. **Every** new event sends its own email; nothing is merged or skipped, except that the company's daily email limit applies. A [duplicate](#duplicates) of an event already received is never emailed again.
3. The event is visible in the **AI events** tab of the company that holds the stream id, and to super admins.

Stream ids are managed in the app, not through the API. See [AI events](/docs/modules/logbooks#ai-events) for how companies add them and what each email status means.

<Note>
The order does not matter for what is shown: events sent before a company adds its stream id appear as soon as it does. Alert emails are different: they are only sent for events that arrive **after** the stream id and its email alerts are set up.
</Note>

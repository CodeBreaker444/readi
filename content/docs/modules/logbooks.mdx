Logbooks are the official record of your operation. There are three, in the sidebar under **Logbooks**. All of them have filters, a search box and a **Refresh** button.

---

## Planned Mission Logbook

All mission plans across your evaluations and plannings.

| Filter | |
|---|---|
| Client, PiC (pilot in command), Evaluation, Planning, System | Narrow by who and what |
| Update From / To | Narrow by date |
| Search | Across all columns |

Columns: client, evaluation, planning, mission description, mission plan, system, version and active status. You can add, edit or delete entries, and open the files attached to a plan. Deleting is permanent.

---

## Flight Logbook

Every flight flown.

**Filters:** date range, PiC, client, drone system, mission type, category, status, result, mission plan and mission group.

**Columns:** start, end, PiC, client, category, type, drone system, status, result, mission plan, flight time, distance and notes.

Use the export option to download the list for audits or authorities. Exported files include the mission ID, dates, pilot, vehicle, result, plan code, flown time and flown meters.

---

## Battery Logbook

Every battery across your systems.

**Filters:** installed from / to, drone system and status.

| Column | Meaning |
|---|---|
| Battery and S/N | Which battery |
| Drone system | Where it is installed |
| Status | Current state |
| Cycle health | How many charge cycles are used against its limit |
| Installed, Last maintenance, Maintenance cycle | Service history |
| Vendor, Purchase date | Origin |

Open a battery for its **Cycle Log**: each mission it was used on, with date, duration, pilot and cycles added, plus the total.

## Event Logbook

Pilots report incidents and anomalies (equipment malfunction, GPS signal issue, obstacle detected, weather, bird activity, unexpected landing, fly-away, other) with **Add Report Event**. Because a flight often has several events, the details they share are set up once, so that adding an event during a flight takes only a few taps.

### Mission setup

The first time you click **Add Report Event** you see **Mission setup**:

- **System** – the drone. If only one is available it is pre-selected. The system's base location is used to open the map.
- **Mission (optional)** – lists all missions of the chosen system, each with its operation type, status (Scheduled, In Progress, Completed, Cancelled or Aborted), category, client and date. A mission that has a mission plan shows it nested underneath. The list can be searched.
- **Takeoff time** – filled from the mission's scheduled start, and can be changed.
- **Notifications** – the contacts to email, pre-selected from the client's defaults.

Save the setup and it is remembered in your browser for 24 hours. From then on **Add Report Event** opens straight to the event screen with these values pre-filled. Use the pencil / **Edit** on the summary to change the setup at any time.

### Reporting an event

The event screen is a single modal with no Next buttons:

1. Check the pre-filled setup summary. Only the **Notify** dropdown can be changed in place.
2. Choose the **event type**.
3. Set the exact **location** by tapping the map or searching, and optionally add attachments (JPG, PNG, MP4, PDF, up to 100 MB each) in the same section. The map opens on the mission plan when there is one, otherwise on the system's base location. When the mission has a plan, its area is highlighted on the map.
4. Add optional notes and click **Submit Event**. **Add Another Event** keeps the setup, so the next event only needs a type and a location.

A pilot can only pick systems and missions assigned to them and only sees the events they reported. Roles that manage systems see every event of the company. The warehouse is never offered as a system.

### Webhooks

Admins, OPMs and super admins see a settings icon on the page to configure webhooks. Each webhook can target **one client** (it then only receives events of that client, resolved from the mission, otherwise from the system's assigned client) or **all clients**, and can be limited to specific event types.

Every new event is sent as an HTTPS `POST` with `event.created`:

```json
{
  "id": "delivery-uuid",
  "type": "event.created",
  "created_at": "2026-10-07T14:20:05.000Z",
  "data": {
    "event_id": 126,
    "event_type": "equipment_malfunction",
    "takeoff_time": "2026-10-07T10:32:00.000Z",
    "location": { "latitude": 42.4097, "longitude": 12.8603, "label": "Rieti, Lazio, Italy" },
    "notes": "Strange vibration from motor",
    "pilot": { "id": 12, "name": "Jane Doe" },
    "drone": { "id": 4, "name": "Lito X1", "code": "LX1" },
    "mission": { "id": 88, "name": "Survey-12", "code": "M-88" },
    "client": { "id": 3, "name": "Acme" },
    "attachments": [{ "file_name": "screenshot.png", "file_type": "image/png", "file_size": 120394, "url": "https://…", "url_expires_in_seconds": 604800 }]
  }
}
```

Verify the `X-Readi-Signature` header: `sha256=` + HMAC-SHA256 (hex) of `"<X-Readi-Timestamp>.<raw body>"` with the webhook's signing secret, which is shown once when the webhook is created or rotated. Respond with any `2xx` within 8 seconds; failed deliveries (network error or `5xx`) are retried once. All deliveries appear in each webhook's delivery log. Endpoints must be public HTTPS URLs.

### Email notifications

Admins, OPMs and super admins also see a **mail icon** next to the webhook settings icon. It opens two tabs:

- **Contact book** – the company's reusable recipients. Each contact has a **name**, an **email** (unique per company), and an optional **company** and **notes**. Contacts can be searched, edited, deleted and sent a test email. Deleting a contact also removes it from all client defaults.
- **Default notifications** – pick a **client** from the dropdown and tick the contacts that should be emailed by default for that client. Defaults are pre-selected whenever an event is reported for that client.

Notifications are **per event**, not per event type: the **Notify** dropdown in the mission setup and on the event screen lists the contact book with the client's defaults already ticked. It shows five contacts at a time, selected ones first, and has a search box to find the rest. The pilot can add or remove contacts (up to 20); the selection is saved with the event. Changing the mission or system before touching the selection re-applies the new client's defaults.

When the event is submitted, the selected contacts receive one email with the event type, report and takeoff times, pilot, drone, client, mission, location, notes and attachment download links (valid for 7 days). Each send counts towards the company's daily email limit; once it is reached, event emails are skipped until the counter resets. Email failures never block the pilot's report.

## New Features

### OPM Approval for Pilot-Created Missions

When a pilot creates a mission, it is now submitted for approval to the OPMs of the pilot's department. Until one of them approves it, the mission stays off the Daily Board and cannot be started, completed, or moved to another state. Missions created by OPMs or managers do not need approval and work exactly as before.

- Any single OPM in the department can approve or deny a request; the first decision is final.
- Recurring missions are approved or denied together as one request.
- The pilot is notified (in the app and by email) of the decision. OPMs and managers in the department are notified (in the app and by email) when a new request arrives, and the email links straight to the Flight Requests page.
- If the pilot's department has no OPM, or the pilot has no department, a warning is shown on the last step of the New Mission screen. The mission can still be created but stays pending, and administrators are notified so it is not forgotten. Administrators can also approve or deny requests.

### Internal and External Flight Requests

The Flight Requests page now has an Internal / External toggle next to the filter and Refresh button, and the page header is always visible.

- **Internal** lists approval requests from your company's pilots with Approve and Deny actions (an optional reason can be added when denying). It can be filtered by All, Pending, Approved, or Denied, shows a badge with the number of pending requests, and is paginated when there are more than 8 requests.
- **External** keeps the existing requests received from other systems, with the same screens and behavior as before.

### Approval Status on the Daily Board and Mission Table

The OPM approval status (Pending, Approved, or Denied) now appears on the Daily Board cards, in the Mission Table, and on the mission details page, where a denial reason is also shown.

### D-Flight Authorization After Approval

For pilot-created missions, the D-Flight authorization request is now sent when the OPM approves the mission instead of at creation. While waiting, the Mission Table shows "D-Flight: Awaiting OPM approval", and "D-Flight: Not submitted" if the request could not be sent after approval so it can be retried. Companies using D-Flight still only see a mission on the Daily Board once D-Flight has accepted it.

## Improvements

### One Maintenance Ticket for Multiple Components

Creating a maintenance ticket for several components now creates a single ticket that lists all of them, instead of one ticket per component. A new ticket can be opened while other tickets are open as long as it covers components that no open ticket already covers.

### Closing Tickets Only Affects What They Cover

Closing a ticket now closes only that ticket, resets the maintenance counters and operational status only for the components it covers, and leaves other open tickets on the same system untouched. A system-level ticket covers every component, and an extraordinary ticket covers the drone components only. The system returns to Operational once its last open ticket is closed.

### Clearer Maintenance Dashboard

Components now show their assigned manufacturer and model, and a system without its own model falls back to the model of its drone component. The last closed ticket on the Daily Board now shows the closing note instead of the original issue description. The maintenance table and its loading skeleton were also refreshed.

### Model Maintenance Cycles Apply to All Components

Changing a model's maintenance cycle and limits now automatically applies to every component using that model.

## Fixes

### Maintenance Dates Set Only for Selected Components

Fixed the last maintenance date being applied to components that were not selected when a ticket was created.

### Unchecked Components Ticket Handling

Fixed maintenance tickets for components that were left unchecked, and fixed extraordinary maintenance offering components other than the drone.

### Maintenance Cycle Limits Read Correctly

Fixed model cycle limits (hours, flights, and days) not being read from the model's saved specifications, which could show them as zero.

## New

### Today's Schedule

Pilots have a new **Today's Schedule** tab in Slot Booking. It lists every slot the pilot is **approved** for today, in time order, as a timeline. "Today" is the date at each slot group's site, so a night slot from yesterday (for example 22:00–06:00) stays on the list until it ends.

- **Header and tiles:** the date, a live clock and the last refresh time, with a shortcut to the Daily Board. Tiles show slots today, hours on duty, missions done out of linked, missions in progress and slots that need attention.
- **Banner:** red when a slot needs attention or some of today's missions are not linked to a slot yet, green when every slot is on track.
- **Slot cards:** time, duration, slot group, client, system, weather, the slot's state and a timer bar that fills as the slot's time passes.

### Link Missions to a Slot

Pilots and the OPM can link the pilot's missions of the day to a slot. The dialog shows the full mission details, marks missions planned inside the slot's time and pre-selects them. A mission belongs to one slot only, a different client shows a warning, and a link can be removed with the **×** on the mission. Every change is written to the slot's audit log.

### Live Mission Progress

Mission status comes straight from the Daily Board. Starting or finishing a mission there shows on Today's Schedule within 20 seconds, when the browser tab is shown again, or at once with **Refresh**. Slot states are: No mission linked, Ready, No progress, In progress, Next mission pending, Completed and Incomplete.

### Renewable Component Expiry

When you add or edit a component, a new **Permanent expiry** checkbox sits under the expiry fields. It is **checked by default**, so nothing changes for existing components: when they expire they are decommissioned for good.

Uncheck it for a component that can be brought back after it expires:

- **On expiry** (expiry date passed, or the flight or flight-hour limit reached), the component shows as **Not Operational** instead of Decommissioned, and its system becomes Not Operational. No ticket is created automatically: you create the maintenance ticket for the component yourself, like for any other component.
- **Make it operational again** by creating a maintenance ticket for the component and closing it. **Closing the ticket renews the expiry automatically**: the expiry date moves 1 month ahead, and flight and flight-hour limits go up by 10. The **Close Ticket** window shows the new values before you confirm.
- **Its expiry cannot be edited while it is expired.** Saving a changed expiry date or limit gives a clear error saying it has to be done through a ticket. Once renewed, you can edit the expiry normally.
- **Or decommission it** by setting its status to Decommissioned. The system then no longer counts it.
- **Permanent expiry:** the system stays Not Operational until the expired component is **removed from the system** (removed, or moved to the warehouse). Setting it to Decommissioned no longer frees the system.
- **Maintenance status on tickets:** when you create a ticket for a system that is Not Operational only because of an expired component (permanent or not), the system now shows **Maintenance** instead of staying Not Operational.
- **Expiry date fix:** setting a component's expiry to today or a past date no longer decommissions it by itself. It reads as Decommissioned and its system becomes **Not Operational**; before, the system could stay Operational. The Edit Component dialog now shows the saved status and only changes it when you do.
- The checkbox is locked while a component is expired, so an expired component cannot be switched from one mode to the other.
- Expiry errors on the Edit Component dialog now appear in the user's selected language (English, German or Italian).

### Client Mission Status URLs

In **Settings → Integrations → DCC server**, a new **Client mission status URLs** card lets you give each client its own URL. Readi sends the status of that client's missions to it, **even when the mission was created in Readi and never came from an external request**.

- **Set up:** search for a client in the dropdown, enter the URL and click **Add / Update**. Picking a client that is already configured shows its current URL. Remove a URL with the bin icon.
- **When it is sent:** a mission is started (**In Progress**) or finished (**Completed**) on the Daily Board, its status is changed from the Operations table, or it is aborted. Missions of a client without a URL send nothing.
- **What is sent:** a `POST` with the mission id and code, name, status, a `note`, and the scheduled, actual start and actual end times.
- A failed delivery never blocks the action in Readi. It is written to the server log.
- The card, its messages and the abort texts follow the selected language (English, German or Italian).

### Abort Missions from the Daily Board

Every mission card in **Scheduled** and **In Progress** has a red **Abort** button. It opens a window with an optional **reason**. Confirming closes the mission, removes it from the board and writes the action to the audit log. The reason is saved on the mission and sent to the client's status URL as the `note`.

- Completed and already aborted missions cannot be aborted.
- The button is shown to users who can edit the Daily Board.
- **Set Aborted** in the Operations table now asks for a reason too.
- Missions aborted automatically because their day passed without starting get the reason "Automatically aborted: scheduled date passed without the mission being started", and are also sent to the client's URL.

## Improvements

### Loading Placeholders

Every Slot Booking tab now shows a placeholder that matches its own layout (cards, tiles, calendar, tables) while data loads, instead of a blank area.

### Steady Tab Bar

Switching Slot Booking tabs no longer hides the tab bar for a moment, and managers no longer briefly see the pilot tab names when the page first opens.

### Time Zones

The Daily Board and the auto-abort job now use the same site-based day as Today's Schedule, so a night slot is not cut off at midnight.

### Documentation

The Slot Booking, Operations and database tables documentation pages describe Today's Schedule and the new slot-to-mission link. The Systems, System Status Rules and Maintenance pages describe the Permanent expiry option. The DCC Integration page describes the client status URLs and the abort reason.

## Fixes

### Update Password Autofill

Browsers no longer fill saved credentials into the new and confirm password fields when an admin or a user updates a password. The fields are marked as new passwords, in both the team and the user management dialogs.

## Regole di validazione dei parametri

### Schemi di validazione comuni

#### Validazione delle stringhe
- Rimuovi gli spazi iniziali e finali prima del salvataggio
- Converti in maiuscolo i codici (tool_code, mission_code, ecc.)
- Rifiuta le stringhe vuote nei campi obbligatori
- Lunghezza massima: 255 caratteri per la maggior parte dei campi

#### Validazione numerica
- Deve essere >= 0 per conteggi e durate
- Deve essere > 0 per limiti e rapporti
- Precisione decimale: 2 cifre decimali per le ore
- Intero per conteggi e ID

#### Validazione delle date
- Deve essere in formato ISO 8601 valido
- La data di fine deve essere >= alla data di inizio (dove applicabile)
- Date future consentite per la programmazione
- Date passate consentite per i record storici

#### Validazione degli enum
- Campi di stato: limitati ai valori enum definiti
- Campi di tipo: limitati ai valori enum definiti
- Flag di attivazione: solo 'Y' o 'N'

#### Validazione JSON
- Deve essere un oggetto JSON valido
- Gli oggetti annidati vengono validati ricorsivamente
- Gli array devono contenere elementi validi
- Null consentito per i campi opzionali

### Validazione specifica per modulo

#### Modulo Manutenzione
- `maintenance_cycle_hour`: Usato solo se > 0
- `maintenance_cycle_flight`: Usato solo se > 0
- `maintenance_cycle_day`: Usato solo se > 0
- `battery_cycle_ratio`: Deve essere > 0, predefinito 1.0
- `component_active`: Solo i componenti 'Y' vengono valutati

#### Modulo Operazioni
- `flight_duration`: Calcolata da actual_start e actual_end
- `max_altitude`: > 120m attiva il flag di conformità
- `battery_charge_start/end`: Deve essere 0-100
- `status_name`: Deve seguire le transizioni definite

#### Modulo E-mail
- `daily_email_limit`: Deve essere > 0
- `notification_roles`: Devono essere ruoli utente validi
- `notification_user_ids`: Devono essere ID utente validi
- `module_name`: Deve essere 'maintenance', 'operations' o 'planning'

#### Modulo Pianificazione
- `planning_status`: Solo 'NEW' può essere eliminato
- `evaluation_status`: Solo 'NEW' può essere eliminato
- `planning_json`: Deve contenere un array di tasks valido

#### Modulo Integrazione
- `flytbase_api_token`: Deve essere un JWT valido
- `flytbase_org_id`: Obbligatorio con il token
- `serial_number`: Corrispondenza senza distinzione tra maiuscole e minuscole
- SN segnaposto: 'n/a', 'na', 'unknown', 'none', '-', 'null' vengono filtrati

## Transizioni di stato dei parametri

### Transizioni di stato della manutenzione

```
OK → ALERT (all'80% del limite)
ALERT → DUE (al 100% del limite)
DUE → OK (dopo la manutenzione, contatori azzerati)
OK → IN_MAINTENANCE (ticket creato)
IN_MAINTENANCE → OK (ticket chiuso)
```

### Transizioni di stato della missione

```
PLANNED → IN_PROGRESS (controllo pre-volo OK, sistema OPERATIONAL)
IN_PROGRESS → COMPLETED (controllo post-volo OK)
IN_PROGRESS → FAILED (flag di incidente)
PLANNED → CANCELLED (azione dell'utente)
```

### Transizioni di stato della pianificazione

```
NEW → PROCESSING (revisione avviata)
PROCESSING → REQ_FEEDBACK (in attesa di approvazione)
REQ_FEEDBACK → POSITIVE_RESULT (approvata)
REQ_FEEDBACK → NEGATIVE_RESULT (rifiutata)
NEGATIVE_RESULT → PROCESSING (revisione)
PROCESSING → TESTING (fase di test)
TESTING → POSITIVE_RESULT (test superati)
TESTING → NEGATIVE_RESULT (test falliti)
```

### Transizioni di stato della valutazione

```
NEW → PROCESSING (valutazione avviata)
PROCESSING → DONE (valutazione completata)
```

### Parametri del registro di audit

| `created_at` | `audit_logs.created_at` | date | Timestamp |

### Parametri sottoposti ad audit

**Parametri ad alto valore (sempre sottoposti ad audit):**
- `tool.tool_active` (attivazione/disattivazione del sistema)
- `maintenance_ticket.ticket_status` (ciclo di vita del ticket)
- `pilot_mission.status_name` (ciclo di vita della missione)
- `public_users.user_active` (attivazione dell'utente)
- `owner.daily_email_limit` (modifiche al limite e-mail)

**Parametri a medio valore (sottoposti ad audit per le modifiche critiche):**
- `tool_component.component_active` (attivazione del componente)
- `planning.planning_status` (approvazione della pianificazione)
- `evaluation.evaluation_status` (completamento della valutazione)

**Parametri a basso valore (non sottoposti ad audit):**
- Nomi visualizzati e descrizioni
- Aggiornamenti dei timestamp
- Incrementi dei contatori (cicli di manutenzione, conteggi e-mail)

### Memorizzazione in cache dei parametri calcolati

**Calcoli in cache:**
- Stato operativo del sistema (calcolato a ogni caricamento della bacheca)
- Stato di manutenzione del componente (calcolato a ogni caricamento della bacheca)
- Conteggio giornaliero e-mail (azzerato ogni giorno, memorizzato in cache nel DB)

**Non in cache (tempo reale):**
- Durata della missione (calcolata su richiesta)
- Telemetria di volo (dall'API FlytBase)
- Risultati della sincronizzazione GUTMA (per ogni operazione di sincronizzazione)
